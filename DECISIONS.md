# Decisions

One line per non-obvious choice made while building the site autonomously.

- Next.js 15.5 (not 16) with React 19, TypeScript 5.9, Tailwind 3.4, ESLint 9, Vitest 3: the newest majors I could verify against the spec's APIs (`output: 'export'`, `tailwind.config.ts`).
- Playwright pinned to 1.56.1 because its Chromium (rev 1194) is the one preinstalled in the build sandbox; CI installs the matching browser.
- The app sits at the repo root (multi-repo rule 1); spec paths `site/…` map to `./…`.
- Data comes from each agent's `data` branch via `scripts/fetch-data.mjs`, configured in `config/sources.json`; config order = overview card order.
- If any required file of an agent is missing, fails to download, or fails the §6 zod contract, that whole agent falls back to `test/fixtures/<agent>/` (never mixed live+sample), and is marked `sample: true` in the site-assembled `manifest.json`.
- Contract failures in live data fall back to fixtures instead of failing the build (user rule: never fail because an agent hasn't published); the build-time loaders still fail on corrupt data in `public/data` (spec §3), which can then only come from committed fixtures.
- `history/` snapshots are fetched best-effort through the GitHub contents API (raw.githubusercontent can't list directories), last 7 only; no v1 page reads them.
- The agents' current repos commit `schemas/*.schema.json` that predate agents-core's `RunMeta` (e.g. macro `meta` has `generated_at`, no `schema_version`) and differ from §6, so I did not vendor them; the §6-exact hand-written zod in `src/lib/schemas/` is the contract.
- `gen:types` generates TS (json-schema-to-typescript) + zod (json-schema-to-zod) only from a live data-branch `schema.json`; otherwise it writes stubs re-exporting the hand-written contract. Pages always use the hand-written contract. No `git diff --exit-code` check in CI, since generated files legitimately change when agents publish.
- Multi-root schemas (e.g. real estate's `IndexOutput` + `MetroDetailOutput`) get one TS namespace per root to avoid helper-type name clashes.
- `fetch-data.mjs` imports the TS zod schemas through `tsx`'s `tsImport`, so there is one contract for scripts, build and browser.
- `ensure-data.mjs` runs before `build`/`dev`: if `public/data` is missing it assembles fixtures offline, so `npm run build` works with no network.
- `public/data`, `public/og`, sitemap and robots are build outputs and gitignored.
- Fixtures are generated by a deterministic, seeded Python script (`scripts/gen_fixtures.py`) so YoY, z-scored temperature, flags, movers and payments are internally consistent; all 50 metros from the real agent's `metros.toml` are included (map and movers need them).
- Fixture payments use the same amortization formula as the site; a unit test checks the calculator reproduces the agent's `payment_now`/`payment_year_ago` exactly.
- `percent` format is ambiguous across agents: real-estate shares are 0–1 ratios, while macro/rates publish percent units. The formatter takes `{ isRatio }`, set from the real-estate registry's `change_kind: pp`; macro handles its `percent_signed` values (already in percent) locally in `components/macro/helpers.ts`.
- `ratio` format renders as a percent (98.7%), per the spec's sale-to-list example.
- Delta formats: day differences render "+9 days", months-of-supply "+0.7"; every delta shows ▲/▼ and a sign.
- Light-theme `--neutral` darkened from spec #8a6d1f to #7a5f14: the spec value is ~4.4:1 on `--surface-2` and failed axe AA.
- Dark theme overrides `--accent-contrast` to #0e1015: white on #6d8cff is ~3:1 and fails AA.
- Tailwind colors use `color-mix(... <alpha-value> ...)` so opacity modifiers (`bg-bad/10`) work on CSS-variable tokens.
- `Sparkline` is a plain SVG, not Recharts, to keep the overview's first-load JS small (111 KB) and render it at build time.
- Recharts is code-split everywhere: the compare chart (`next/dynamic`, ssr:false), macro cards (loaded on expand), and the yield curve (loaded when scrolled near). This took `/real-estate` from 251 KB to 141 KB first-load JS and `/macro` from 253 KB to 118 KB.
- Inter uses `display: 'optional'`: with `swap`, the font swap became the mobile LCP (~3.8 s). Lighthouse mobile went 88 → 98 on `/`.
- The OG images for every route (not only `[slug]`) are pre-rendered by `scripts/gen-og.mjs` (satori + resvg, using the Noto Sans TTF bundled with Next) instead of `opengraph-image.tsx`, so there is one pipeline that works under the Pages basePath.
- Metro map uses Leaflet `CircleMarker`s (no icon assets); OSM tiles via `NEXT_PUBLIC_MAP_TILES` override; dark mode uses a CSS filter on the tile pane.
- Map click when 3 metros are selected replaces the oldest (spec); the table fallback has a "Compare" button per row.
- Explorer state is mirrored to the URL but also kept locally, so controls update instantly while `router.replace` catches up; `?m=` (empty) means "explicitly cleared", not "use defaults".
- Stat-table best/worst highlights only apply to metrics with a good direction; for neutral metrics (most housing metrics) no side is "better", so no highlight.
- A chart note appears when compared series differ by more than 20× (e.g. U.S. totals vs metros).
- The affordability calculator keeps a price the user typed even if the metro file finishes loading afterwards.
- Base path: `BASE_PATH` env wins, else `/<repo>` on GitHub Actions; the deploy workflow sets `BASE_PATH=/agents-hub` so the build, sitemap, e2e server and Lighthouse agree.
- `scripts/serve-out.mjs` serves `out/` under the basePath with gzip (like Pages) for e2e and Lighthouse; without gzip, Lighthouse numbers were ~3× worse than production.
- E2E reads the data actually built (`out/data`) for expectations, so the same tests run against fixtures or live data.
- `@axe-core/playwright` bundles a newer playwright-core; the `Page` type is cast in the a11y spec (runtime API is compatible).
- Leaflet's own container is excluded from axe (third-party); the accessible table fallback is tested instead.
- Macro, Grants and Repos pages were built by parallel subagents confined to their own directories; I reviewed, integrated, and fixed shared issues (Tailwind alpha, lazy charts, tests) afterwards.
- The "evals" claim on /about is limited to the grants and repo agents, which have eval folders in their repos.
- Below-the-fold heavy pieces render via `WhenVisible` (IntersectionObserver): the real-estate compare chart, the Leaflet map and the macro yield curve. `/real-estate` mobile Lighthouse went from 84–91 to 92–98.
- The contract stays §6-exact even where a real agent output differs by one enum (repo-maint's committed sample uses `narrative_source: "deterministic"`); that agent falls back to sample data until it emits `"template"`. Flagged in STATUS.md.
- Site `meta` = agents-core `RunMeta` with `.passthrough()`: any `1.x` schema_version (only the major is enforced), optional `warnings: string[]`, unknown agent-specific meta keys kept; agent `.extend()`s still type-check their known extras. Bodies unchanged (zod's default strip, exact field shapes and enums).
- Agent deviations found in real output are tolerated narrowly in the schema with a `TODO(<agent>)` and normalized to the contract value (repo_maint `"deterministic"` → `"template"`; real_estate `days_signed`/`months_signed` → `days`/`decimal1`, other `*_signed` → null), so the site goes live instead of falling back; listed in STATUS.md "Agent-side fixes needed". This supersedes the earlier "§6-exact, fall back" choice for repo-maint.
- Real outputs were produced locally without spending: real_estate/macro reused committed LLM caches (0 calls); grants ran once with no LLM (unscored) and once with the agent's own test `FakeClient` over the same cached live data. Both grants variants are kept as fixtures (`grants`, `grants__fake-llm`).
- `fetch-data` tells missing repo / missing `data` branch / missing file apart with `git ls-remote` rather than the GitHub API: the unauthenticated API rate limit (60/h) was already exhausted in the sandbox and would make the reason unreliable.
- Fallback reasons are structured (`kind`, `file`, `message`, zod `issues[]` with paths) in `_fetch-report.json`; the log prints up to 10 issue paths per agent plus a summary table, and the same table goes to `$GITHUB_STEP_SUMMARY` on Actions.
- Non-404 4xx responses aren't retried; 5xx/429/network errors retry 3× with backoff. Optional files (schema.json, history) never cause a fallback, but a skipped one is logged as a warning.
- `fetch-data --local <agent>=<dir>` and `FETCH_OUT_DIR` exist so a real run can be checked end to end (build + e2e) before it's published, and so the fetch-data test doesn't touch `public/data`.
- The macro e2e no longer assumes a revision badge: it expects one only when the built data has a revision (a live no-revision day is valid).
- Agentic additions (agents-core v0.3.0 `trace.json`/`trace_summary`, the agents' §6.x outputs) live in `src/lib/schemas/agentic.ts`; the §6 bodies stay exact, but the new fields attach with `lenient()`/`lenientArray()` so a malformed one is dropped (field or array item), never sending the agent to sample data. `fetch-data` checks them strictly (`AGENTIC_FIELDS`) and logs a warning with the path.
- I first built the four agentic outputs against guessed shapes (the agent specs hadn't landed); when all four agents published their §6.x on 2026-09-27 I replaced the guesses with their exact shapes rather than supporting both (one contract per field; no data was ever published in the guessed shapes).
- Evals and case studies are read from each repo's default branch (`config/sources.json` `repo_files`), not the `data` branch, because that's where agents-core writes `evals/history.jsonl` and where the docs live; each file falls back to a committed sample on its own, with its own badge ("Sample evals" / "Sample write-up"), independent of the agent's data status.
- agents-mcp's eval history has no `suite` and uses `date`/`cost_usd`; lines are normalized to agents-core's shape, its suite named via `eval_sources[].default_suite`, and non-0–1 "scores" (`n`) moved to counts so they aren't charted as percentages.
- Eval history is normalized and written as JSON (`public/data/evals/<id>.json`) at build time; the latest-scores table renders server-side (no JS), the history chart is a lazy Recharts client component that fetches that file.
- Eval deltas are "±N pts" against the previous run of the same suite with ▲/▼ and good=up tone; under half a point is flat (no arrow), so rounding noise isn't colored.
- The Run trace panel renders the roll-up at build time and keeps spans out of page props: `trace.json` (up to 256 KB) is fetched, and the timeline/table code (`TraceView`) loaded via `next/dynamic`, only when the panel is opened.
- The trace timeline is plain HTML/CSS bars (no chart library): every row carries its kind as text next to the color swatch, and a screen-reader sentence with start offset and duration; the "Table" view is the text fallback.
- Unknown span kinds read as `custom` and `trace_schema_version` must be 1.x, so a future agents-core span kind doesn't break the panel but a new trace major does (the trace is optional, so that only hides the panel).
- The macro "what's driving this" card shows cited series with their current value from the page's own indicators, not from the analysis text, so the numbers can't drift from the dashboard.
- Grants bid research lists USAspending citations separately from other sources (the notice, attachments), because they back the prior-awards table the brief relies on.
- Fix proposals: `proposed` and `pr_opened` read "Draft PR — awaiting human review" (a draft PR is still unreviewed); the approval id is shown with how a maintainer approves it; `no_fix`/`stopped`/`approval_blocked`/`failed` get plain labels with `reason`.
- Diff preview keeps the `+`/`-` characters in the text (color is a second cue), shows 28 lines and collapses the rest behind a native `<details>` unless fewer than 12 would be hidden.
- Agent text renders `backtick` spans as `<code>` (`InlineText`) and nothing else — no Markdown or HTML from agent output outside the sanitized case studies.
- Case studies render with react-markdown + rehype-sanitize (no raw HTML); relative links resolve like GitHub (to the repo's blob URL, images to raw), `javascript:`/`data:` links are dropped, the file's own `# Title` line is replaced by the section heading, and long inline code wraps (`overflow-wrap:anywhere`) so 360px screens don't scroll sideways.
- /mcp content comes from agents-mcp's README (install commands, tools, prompts, config, example conversations) as a typed module (`src/components/mcp/content.ts`), so it's static HTML; only the copy buttons are client code.
- The desktop nav now starts at `lg` (7 items don't fit at `md`); below that the existing menu sheet is used.
- Sample traces are generated on a simulated clock with agents-core's summary formula, and LLM span costs are scaled to each fixture run's `cost_usd`, so the trace panel and the published run cost agree.
- The README hero GIF is built from lossless Playwright screenshots with explicit hold times (not a recorded video: webm codec noise made every GIF frame differ, 9 MB+), one shared ffmpeg palette, no dithering, 1000px wide: 2.5 MB for 20 s. ffmpeg comes from `$FFMPEG` (e.g. `pip install imageio-ffmpeg`), not an npm dependency.
- The contract helpers in `scripts/lib/contracts.mjs` import `tsx` lazily, so tests can use `agenticWarnings` without esbuild in jsdom.
